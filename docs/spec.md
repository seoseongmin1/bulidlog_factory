# 기능 동작 설명서

[PRD.md](PRD.md)의 기능 9개가 사용자에게 어떻게 동작해야 하는지 정리한 문서입니다. PRD로 판단할 수 없던 내용은 확인을 거쳐 반영했습니다.

## 1. 모든 기능의 공통 조건

| 항목 | 내용 |
|---|---|
| 사용 환경 | 내 컴퓨터에서만 시연합니다. 온라인에 공개하지 않습니다. |
| 로그인 | 없습니다. 그래서 사용자별 권한 구분도 없습니다. |
| 볼 수 있는 사람 | 시연하는 컴퓨터의 화면을 보는 사람 |
| 원본 데이터 | 2018년 대우스틸 광양 공장 데이터 한 가지만 씁니다. 다른 데이터를 올릴 수 없습니다. 이 데이터는 데이터베이스에 들어 있고 앱은 읽기만 합니다. |
| 보관되는 것 | 사용자의 질문, 대화, 보고서, 접속 정보는 데이터베이스에 저장하지 않습니다. 저장한 보고서 파일은 사용자의 컴퓨터에만 있습니다. 경보에 대한 작업자의 대응 기록(기능 9)은 이 컴퓨터의 파일에만 저장합니다. 한눈에 보기의 AI 문장은 같은 날짜를 다시 열 때 빨리 보이도록 서버를 끌 때까지만 서버 메모리에 둡니다. 경보 예측 모델도 서버를 끌 때까지만 서버 메모리에 둡니다. |
| 수정·삭제 | 앱 안에서 원본 데이터를 수정하거나 삭제할 수 없습니다. |
| 데이터 불러오기 실패 | 실패한 영역에만 안내문과 다시 시도 버튼을 보여 줍니다. 다른 기능은 계속 쓸 수 있습니다. 데이터베이스에 연결하지 못하는 경우도 여기에 포함합니다. |

## 2. 기능 1: 한눈에 보는 대시보드

### 사용자가 하는 일

- 입력할 항목은 없습니다.
- 앱을 열어 숫자 카드와 그래프를 봅니다.

### 정상 결과

- **저장:** 새로 저장되는 것은 없습니다.
- **화면:** 1년 치 사용량을 보여 주는 숫자 카드, 월별 그래프, 시간대별 그래프, 날짜별 그래프가 보입니다.

### 실패했을 때

- 입력이 없으므로 잘못 입력하는 경우는 없습니다.
- 데이터를 불러오지 못하면 대시보드 영역에 안내문과 다시 시도 버튼이 보입니다.

### 보기와 수정·삭제

- 시연 컴퓨터의 화면을 보는 사람은 누구나 볼 수 있습니다.
- 내용을 수정하거나 삭제할 수 없습니다.

### 제대로 만들었는지 확인하는 방법

- [ ] 앱을 열면 입력 없이 숫자 카드와 그래프 3개가 보인다.
- [ ] 1년 총 사용량이 959.6MWh로 표시된다.
- [ ] 월별 그래프에 1월부터 12월까지 12개월이 모두 있다.
- [ ] 날짜별 그래프에 1월 1일부터 12월 31일까지 이어져 있다.
- [ ] 불러오기에 실패하면 대시보드 영역에 안내문과 다시 시도 버튼이 보이고, 다른 기능은 계속 쓸 수 있다.

## 3. 기능 2: 이상한 날 찾기

### 사용자가 하는 일

- 입력할 항목은 없습니다.
- 화면의 이상한 날 목록을 봅니다.
- 목록의 날짜를 누르면 **하루 보기** 카테고리로 옮겨 그날의 한눈에 보기와 일일 보고서가 열립니다.

### 정상 결과

- **저장:** 새로 저장되는 것은 없습니다.
- **화면:** 탐지된 날 중 상위 8일이 이상 점수가 큰 순서로 보입니다. 날마다 사용량이 많은지 적은지 표시하고, 공휴일이면 공휴일 이름도 함께 보여 줍니다.

### 실패했을 때

- 입력이 없으므로 잘못 입력하는 경우는 없습니다.
- 데이터를 불러오지 못하면 이상한 날 목록 영역에 안내문과 다시 시도 버튼이 보입니다.

### 보기와 수정·삭제

- 시연 컴퓨터의 화면을 보는 사람은 누구나 볼 수 있습니다.
- 목록을 수정하거나 삭제할 수 없습니다.

### 제대로 만들었는지 확인하는 방법

- [ ] 목록에 정확히 8일이 보인다.
- [ ] 1위는 사용량이 많은 2018년 12월 16일이다.
- [ ] 2018년 1월 1일은 사용량이 적은 날로 보이고 공휴일 이름이 신정으로 표시된다.
- [ ] 평일은 평일끼리, 주말은 주말끼리 앞뒤 4주와 비교한 결과다.
- [ ] 목록의 날짜를 누르면 그날의 일일 보고서가 보인다.

## 4. 기능 3: 일일 보고서 자동 생성

### 사용자가 하는 일

| 행동 | 조건 |
|---|---|
| 날짜 선택 | 2018년 1월 1일부터 12월 31일까지 고를 수 있습니다. 처음에는 2018년 12월 16일의 보고서가 보입니다. |
| 저장 버튼 누르기 | 선택 사항입니다. 보고서가 화면에 보일 때 누릅니다. |

### 정상 결과

- **날짜를 고르면:** 새로 저장되는 것은 없습니다. 그날의 사용량, 평소 대비 차이, 최대 사용 시각 등이 표로 보입니다.
- **저장 버튼을 누르면:** 보고서가 브라우저의 다운로드 폴더에 `.md` 파일 1개로 저장됩니다. 파일 이름은 `energy-report-2018-12-16.md`처럼 날짜를 넣어 만듭니다.

### 실패했을 때

- 범위를 벗어난 날짜를 직접 입력하면 고를 수 있는 기간을 안내문으로 알려 줍니다.
- 보고서를 만들지 못하면 보고서 영역에 안내문과 다시 시도 버튼이 보입니다.
- 파일 저장에 실패하면 보고서 영역에 안내문과 다시 시도 버튼이 보입니다.

### 보기와 수정·삭제

- 화면의 보고서는 시연 컴퓨터의 화면을 보는 사람이 볼 수 있고, 앱에서 수정하거나 삭제할 수 없습니다.
- 저장한 파일은 앱 밖의 파일이므로, 그 컴퓨터를 쓰는 사람이 보거나 수정·삭제할 수 있습니다.

### 제대로 만들었는지 확인하는 방법

- [ ] 앱을 열면 2018년 12월 16일의 보고서가 보인다.
- [ ] 2018년 12월 16일의 보고서에 사용량 2,014.66kWh, 평소 대비 +450%가 보인다.
- [ ] 2019년 1월 1일처럼 범위 밖 날짜를 입력하면 고를 수 있는 기간이 안내된다.
- [ ] 다른 날짜로 바꾸면 표 내용도 그 날짜로 바뀐다.
- [ ] 저장 버튼을 누르면 다운로드 폴더에 선택한 날짜가 이름에 들어간 `.md` 파일이 생긴다.
- [ ] 저장한 파일을 열면 화면의 보고서와 내용이 같다.

## 5. 기능 4: 말로 묻는 AI 에이전트

### 사용자가 하는 일

| 행동 | 조건 |
|---|---|
| 질문 입력 후 보내기 | 평소 말투로 입력합니다. 내용이 있어야 하고 최대 2,000자입니다. |
| 추천 질문 누르기 | 선택 사항입니다. PRD에서 정한 4개 중 하나를 고릅니다. |

### 정상 결과

- **저장:** 대화 기록을 저장하지 않습니다. 화면을 새로고침하거나 창을 닫으면 대화가 사라집니다.
- **화면:** 분석 진행 상황이 보이고, 이어서 그래프와 AI의 설명이 보입니다.
- **답변 원칙:** 숫자는 분석 프로그램의 계산 결과를 씁니다. 사실과 추측을 나누고, 원화 금액은 제시하지 않습니다.
- **이어서 묻기:** 화면이 열려 있는 동안에는 이전 질문에 이어서 물을 수 있습니다.
- **경보 예측 질문:** 기능 6의 예측을 도구 3개로 씁니다. 한 시각의 예측(`forecast_alarm`), 하루 경보 구간과 실제 초과 구간(`get_alarm_timeline`, 15분 수요전력 그래프), 기간의 경보 횟수·헛경보·시간대별 경보 칸 수(`summarize_alarms`, 시간대별 막대그래프)입니다. AI는 예측을 단정하지 않고 확률과 위험 정도로 말하며, 헛경보와 채점 결과를 함께 알리고, 1~8월은 학습 기간이라고 밝힙니다.

### 실패했을 때

- 빈 질문은 보내지지 않고 화면도 바뀌지 않습니다.
- 2,000자를 넘게 입력할 수 없습니다.
- 데이터로 답할 수 없는 질문을 받으면 AI가 이유를 설명하고 답할 수 있는 범위를 알려 줍니다. 숫자를 지어내지 않습니다.
- AI에 연결하지 못하거나 API 키가 없으면 대화 영역에 이유를 안내합니다. 사용자는 질문을 다시 보낼 수 있고, 대시보드와 보고서는 계속 쓸 수 있습니다.

### 보기와 수정·삭제

- 대화는 시연 컴퓨터의 화면을 보는 사람이 볼 수 있습니다.
- 보낸 질문이나 받은 답변을 수정하는 기능은 없습니다.
- 대화 기록을 저장하지 않으므로 별도로 삭제할 기록도 없습니다.

### 제대로 만들었는지 확인하는 방법

- [ ] 빈 칸으로 보내기를 눌러도 질문이 보내지지 않는다.
- [ ] 2,000자를 넘게 입력할 수 없다.
- [ ] 추천 질문 4개를 누르면 각각 실제 데이터를 바탕으로 답한다.
- [ ] 답변 뒤에 "그것도 자세히 알려줘"라고 물으면 앞의 대화를 이어서 답한다.
- [ ] 새로고침하면 대화가 사라지고 이전 내용을 이어 가지 않는다.
- [ ] 답변의 숫자가 분석 프로그램의 계산 결과와 같다.
- [ ] 그래프의 값이 분석 프로그램의 계산 결과와 같다.
- [ ] 12월 16일의 사용량이 많은 이유를 물으면 원인을 단정하지 않고 가능성과 확인 방법을 말한다.
- [ ] "2019년 사용량은?"이나 "점심 메뉴 추천해줘"라고 물으면 이유와 답할 수 있는 범위를 알려 주고 숫자를 지어내지 않는다.
- [ ] API 키 없이 질문하면 대화 영역에 이유가 보이고, 대시보드와 보고서는 계속 쓸 수 있다.
- [ ] 비용을 물어도 원화 금액을 제시하지 않는다.
- [ ] 기계를 제어하라고 요청해도 제어하지 않는다.
- [ ] "10월 10일 오후 1시에 위험해?"라고 물으면 사용량 위험(57%)과 헛경보가 있다는 점을 함께 말한다.
- [ ] "12월에 사용량 경보가 가장 많은 시간대는?"이라고 물으면 07시(43칸)를 말하고, 칸 수가 경보 횟수가 아니라는 점을 틀리지 않는다.
- [ ] "2019년 1월 1일 오전 9시에 위험해?"라고 물으면 데이터 기간 밖이라고 말하고 숫자를 지어내지 않는다.

## 6. 기능 5: 한눈에 보기 (자동 요약)

### 사용자가 하는 일

| 행동 | 조건 |
|---|---|
| 날짜 고르기 | 일일 보고서의 날짜를 그대로 씁니다. 이상한 날 목록에서 날짜를 눌러도 됩니다. 따로 입력하는 것은 없습니다. |

### 정상 결과

- **상태 신호등:** 분석 프로그램이 정합니다.

  | 상태 | 조건 |
  |---|---|
  | 이상 (빨강) | 이상한 날로 판정된 날. 단, 쉬는 날에 적게 쓴 날은 제외합니다. |
  | 주의 (노랑) | 쉬는 날에 적게 써서 이상으로 판정된 날, 평소와 50% 이상 다른 날, 역률이 85% 미만인 날 |
  | 좋음 (초록) | 위에 해당하지 않는 날 |

  역률 기준은 90%이지만, 이 공장은 하루 역률이 90%를 밑도는 날이 절반이라 주의는 85% 미만에서만 띄웁니다. 85~90%는 문장에서 "조금 낮아요"라고 알립니다. 이 기준으로 2018년은 좋음 249일, 주의 93일, 이상 23일입니다.
- **세 줄 요약:** ① 얼마나 썼는지와 평소(같은 평일·주말 기준)와의 비교, ② 가장 많이 쓴 시각과 그때의 전력, ③ 전기 효율(역률)과 판단. 쉬는 날이면 이름을 함께 씁니다.
- **할 일:** 이상(많음)은 작업일지 확인, 이상(적음)은 설비 정지·휴무 확인, 역률 85% 미만은 콘덴서 점검, 평소와 50% 이상 차이는 작업 일정 확인, 그 밖에는 "따로 할 일은 없어요"를 보여 줍니다.
- **말투:** 존댓말의 짧은 문장으로 쓰고, kVarh·부하·기준선 같은 말은 쓰지 않습니다. 역률은 "전기 효율(역률)"이라고 씁니다.
- **AI 문장:** 프로그램이 만든 요약을 먼저 바로 보여 주고, AI가 쉬운 말로 다듬은 문장이 오면 바꿉니다. AI 문장의 숫자는 모두 프로그램이 준 숫자 안에 있어야 합니다. 화면 아래에 누가 정리했는지(AI 또는 계산) 표시합니다.

### 실패했을 때

- API 키가 없거나 AI가 실패하거나 AI 문장이 조건에 맞지 않으면, 프로그램이 만든 요약을 그대로 보여 줍니다. 오류 안내는 띄우지 않습니다.
- 데이터를 불러오지 못하면 이 영역에만 안내문과 다시 시도 버튼을 보여 줍니다.
- 범위 밖 날짜에는 이 영역을 보여 주지 않습니다. 안내는 일일 보고서에 나옵니다.

### 보기와 수정·삭제

- 시연 컴퓨터의 화면을 보는 사람이 볼 수 있습니다. 앱에서 수정하거나 삭제할 수 없고, 파일로 저장하지 않습니다.

### 제대로 만들었는지 확인하는 방법

- [ ] 앱을 열면 2018년 12월 16일이 **이상**(빨강)으로 보이고, 2,015kWh와 평소 주말의 5.5배, 작업일지 확인이 보인다.
- [ ] 2018년 1월 1일은 **주의**이고 "신정"이 보이며 할 일은 "따로 할 일은 없어요"다.
- [ ] 2018년 6월 20일은 **좋음**이다.
- [ ] 요약의 숫자가 일일 보고서의 숫자와 같다.
- [ ] API 키를 빼도 요약이 나온다.
- [ ] AI 문장이 오기 전에도 요약이 바로 보인다.

## 7. 기능 6: 경보 예측 (조기 대응)

### 사용자가 하는 일

| 행동 | 조건 |
|---|---|

- **모델:** 머신러닝 분류 모델(scikit-learn HistGradientBoosting)을 씁니다. 대상마다 하나씩 둡니다.

  - **AI(OpenAI)는 예측하지 않습니다.**
- **학습과 채점:** 1~7월로 학습하고, 8월로 주의·위험 문턱을 정하고, 9~12월로 채점합니다. 1~8월 시각을 고르면 "학습에 쓴 기간이라 실제보다 잘 맞아 보일 수 있어요"를 함께 보여 줍니다.
- **위험 정도:** 문턱은 8월의 실제 초과를 기준으로 정합니다.

  | 정도 | 조건 | 사용량 문턱 | 역률 문턱 |
  |---|---|---|---|
  | 위험 (빨강) | 8월의 실제 초과 중 50%를 잡는 확률 이상 | 약 49% | 약 66% |
  | 주의 (노랑) | 8월의 실제 초과 중 80%를 잡는 확률 이상 | 약 9% | 약 15% |
  | 좋음 (초록) | 그 밖 | | |

  주의 문턱이 낮은 것은 일부러 정한 것입니다. 놓치지 않는 쪽을 택했습니다. 9~12월에 "위험"이 나왔을 때 실제로 넘은 비율은 사용량 74%, 역률 60%입니다.
- **보여 주는 숫자:** 위험 정도, 확률(%), 지금 값(kW 또는 %), 기준을 보여 줍니다. 화면 아래에 지금 쓰는 모델의 9~12월 채점 결과와 "예측은 확률이라 틀릴 수 있어요. 경보는 알리기만 하고 기계를 제어하지 않아요."를 함께 보여 줍니다.
- **할 일:** 정해진 문장을 그대로 씁니다. AI로 다듬지 않습니다.

  |---|---|---|---|
  | 사용량 | 1시간 안에 기준을 넘을 가능성이 높아요. 큰 설비를 한꺼번에 켜지 말고 순서를 나눠 주세요. | 기준을 넘을 수도 있어요. 큰 설비를 켜기 전에 지금 사용량을 확인해 주세요. | 따로 할 일은 없어요. |
  | 역률 | 전기 효율(역률)이 85% 아래로 떨어질 가능성이 높아요. 콘덴서가 켜져 있는지 확인해 주세요. | 전기 효율(역률)이 떨어질 수 있어요. 콘덴서 상태를 살펴봐 주세요. | 따로 할 일은 없어요. |

## 8. 기능 7: 역률 개선 계산기

### 사용자가 하는 일

### 정상 결과

- **보는 시간:** 09~22시이고, 사용량이 0인 칸은 뺍니다. 경보 예측과 같은 시간입니다.
- **필요한 보상량:** 15분 칸마다 `유효전력 × (지금 tanφ − 목표 tanφ)`로 목표까지 줄여야 할 무효전력(kVar)을 구합니다. 중앙값, 상위 10%, 상위 5%, 최대를 보여 줍니다.
- **자동 역률 조정기 추천:** 10kVar 단위로 필요한 만큼만 켜고, 과보상(진상)이 되면 한 단계 덜 켜는 방식으로 계산합니다. 09~22시 칸의 **95% 이상**이 목표를 넘는 가장 작은 용량을 0~300kVar에서 찾습니다.
  - 0kVar이면 "콘덴서를 더 달 필요가 없어요"를 보여 줍니다.
  - 300kVar로도 안 되면 "맞출 수 없어요"를 보여 줍니다.
- **고정 콘덴서 비교:** 추천 용량과 같은 용량을 09~22시 내내 켜 두었을 때의 목표 미달 칸 비율과 과보상 칸 비율을 보여 줍니다. 미달이 지금보다 늘면 빨간 테두리와 "자동 조정기를 권해요"를 보여 줍니다.
- **그래프:** 시간대별(09~21시) 평균 부족 무효전력(kVar) 막대그래프입니다.
- **2018년 1년 결과:**

  | 목표 | 지금 미달 칸 | 자동 조정기 추천 | 설치 후 미달 칸 | 같은 용량 고정 콘덴서 미달 칸 (과보상) |
  |---|---|---|---|---|
  | 85% | 5.7% | 10kVar | 3.5% | 25.2% (42.5%) |
  | 90% | 20.5% | 40kVar | 4.5% | 40.9% (48.3%) |
  | 95% | 43.9% | 90kVar | 4.0% | 51.1% (62.1%) |

  보상이 가장 부족한 시간대는 11시입니다(목표 90%에서 평균 24.5kVar).
- **주의 문구:** "15분 평균으로 한 산술 계산입니다. 순간 변동, 고조파, 설비 위치는 반영하지 않았으므로 실제 용량은 현장 측정과 전문가 검토로 정하세요. 금액은 계산하지 않습니다."
- **AI 에이전트:** `plan_power_factor_correction` 도구로 같은 계산을 쓰고, 같은 그래프를 대화에 보여 줍니다.

### 정상 결과

- **이유:** 서버가 계산합니다. 입력을 네 묶음으로 나눠 한 묶음씩 학습 기간의 중앙값으로 바꾸고, 확률이 몇 %p 내려가는지 잽니다. 3%p 이상 올린 묶음만 큰 순서로 최대 3개 보여 줍니다.

  | 묶음 | 문장에 쓰는 값 |
  |---|---|
  | 방금까지의 흐름 | 지금 값(사용량은 기준 대비 %), 1시간 전과의 차이 |
  | 평소 패턴 | 앞으로 1시간 평소(지난 4주) 가장 높은 사용량 또는 가장 낮은 역률 |
  | 시간대·요일 | 요일 종류와 한 시간 뒤 시각 |
  | 어제·지난주 같은 시각 | 어제 같은 시각의 값 |

  숫자는 모두 데이터에서 읽은 값입니다. 이유는 모델이 이렇게 판단했다는 증명이 아니라, 입력을 바꿔 본 결과입니다.
- **응답 기록:** 시각, 대상(사용량·역률), 경보 단계, 그때의 확률(%), 응답, 기록한 시각을 `backend/local/alarm_responses.json`에 저장합니다. 이 폴더는 Git에 올리지 않습니다. 데이터베이스에는 쓰지 않습니다.
- **통계:**
  - 대상별 기록 수와 응답별 수, "조치함과 오경보 중 오경보 비율"(무시함은 맞았는지 알 수 없어 뺍니다)
  - 주의 문턱을 10~50%로 올렸을 때(지금 문턱보다 높은 것만) 사라지는 오경보 수와 놓치는 조치 수. 오경보로 기록하고 확률이 그 문턱 미만인 경보가 "사라지는 오경보", 조치함으로 기록하고 확률이 그 문턱 미만인 경보가 "놓치는 조치"입니다.
  - 시간대별 오경보 기록 막대그래프
- **경보 기준은 자동으로 바뀌지 않습니다.** 통계는 참고용이고 기준은 사람이 정합니다.

## 12. PRD에서 그대로 가져온 조건

- 화면은 하나이며 왼쪽에 데이터, 오른쪽에 AI 대화를 둡니다. 왼쪽은 카테고리 탭(개요, 하루 보기, 이상한 날, 경보 예측, 감시 재생, 역률 개선)으로 나눠 하나만 보여 줍니다. 다른 카테고리로 옮겨도 고른 날짜와 시각은 남고, 주소 끝의 `#카테고리`(예: `#forecast`)로 바로 열 수 있습니다.
- 이상한 날 목록은 상위 8일을 이상 점수가 큰 순서로 보여 줍니다.
- 보고서는 화면의 버튼으로 `.md` 파일로 저장합니다.
- 첫 버전은 내 컴퓨터에서만 시연합니다.

## 13. 이 문서에서 다루지 않는 내용

PRD의 제외 기능은 여기서도 만들지 않습니다. 실시간 설비 연결, 기계 제어, 전기요금 계산, 기계별 원인 확정, 로그인, 대화 기록 저장, 다른 공장 데이터 업로드, 온라인 공개가 해당합니다.
