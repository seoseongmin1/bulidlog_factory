# 제작 주문서 (PRD)

> **PRD란?** 무엇을, 누구를 위해, 어디까지 만들지 적은 제작 주문서입니다. 만드는 사람은 이 문서를 보고 작업하고, 완성 여부도 이 문서로 판단합니다.

| 항목 | 내용 |
|---|---|
| 서비스 이름 | 공장 에너지 에이전트 |
| 한 줄 소개 | 공장의 전기 사용 기록을 AI에게 말로 물어보면 직접 분석해 설명하고, 교대 인수인계처럼 반복되는 문서 작업은 AI가 알아서 써 주는 앱 |
| 만드는 목적 | 포트폴리오와 공모전 출품 |
| 만드는 방식 | 서버는 FastAPI, 화면은 React, 전력 데이터는 Supabase 데이터베이스에 보관합니다. 자동 테스트에는 SQLite를 씁니다. |

## 1. 누가 사용하나요?

| 사용자 | 하려는 일 |
|---|---|
| 공장의 에너지 담당자, 생산관리자 | 전기 사용 현황을 확인하고 보고합니다. |
| 생산직 작업자 | 어려운 표나 질문 없이, 그날 전기 상태가 괜찮은지와 할 일이 있는지만 빠르게 확인합니다. |
| 공모전 심사위원, 채용 담당자 | 시연을 보고 이 프로젝트를 평가합니다. 첫 버전의 1차 관람객입니다. |

첫 버전은 실제 공장에 납품하는 제품이 아닙니다.

## 2. 어떤 불편을 해결하나요?

| 지금의 불편 | 서비스가 돕는 방법 |
|---|---|
| 15분마다 쌓인 기록이 1년에 3만 5천 줄이 넘어 읽기 어렵습니다. | 숫자 카드와 그래프로 한눈에 보여 줍니다. |
| 쉬는 날 전기를 많이 써도 표만 봐서는 눈에 띄지 않습니다. | 평소와 다른 날을 자동으로 찾아 줍니다. |
| 숫자를 모으고 계산해서 보고서를 만드는 데 손이 많이 갑니다. | 날짜만 고르면 일일 보고서를 만들어 줍니다. |
| 궁금한 내용을 확인하려면 직접 데이터를 찾고 계산해야 합니다. | 평소 말투로 물으면 AI가 분석해서 설명합니다. |
| 생산직은 보고서 표와 전문용어(역률, kVarh)를 읽기 어렵고, AI에게 무엇을 물어야 할지도 모릅니다. | 날짜만 고르면 상태 신호등과 쉬운 세 줄 요약, 할 일을 자동으로 보여 줍니다. |
| 전기를 많이 쓰거나 역률이 떨어진 뒤에야 알게 되어 미리 대응할 수 없습니다. | 앞으로 1시간 안에 기준을 넘을 가능성을 미리 알려 줍니다. |
| "콘덴서 점검"이라는 할 일만으로는 무엇을 얼마나 해야 할지 모릅니다. | 역률을 목표까지 올리는 데 필요한 콘덴서 용량과 방식을 계산해 줍니다. |
| 교대가 끝날 때마다 경보·사용량·조치 내용을 손으로 모아 인수인계서를 씁니다. 바쁘면 응답하지 않은 경보가 다음 조로 넘어가지 않습니다. | 교대가 끝나면 AI가 인수인계서를 자동으로 쓰고, 미응답 경보를 따로 넘기며, 메신저로 보냅니다. |
| 경보가 울려도 매뉴얼의 어디를 봐야 할지 모릅니다. | 경보 카드와 AI 답변에 해당 매뉴얼 절을 출처와 함께 붙여 줍니다. |
| AI가 말한 숫자를 믿어도 되는지 알 수 없습니다. | 답변의 숫자를 계산 결과와 자동으로 대조해 화면에 표시합니다. |

목표는 담당자가 **숫자를 찾는 시간을 줄이고 무엇을 할지 판단하는 데 집중**하게 하는 것입니다.

## 3. 사용하는 데이터

대우스틸 광양 공장의 2018년 1년 치 전력 측정 데이터를 사용합니다.

| 항목 | 내용 |
|---|---|
| 측정 간격 | 15분마다 1번 |
| 데이터 양 | 35,040건 |
| 들어 있는 정보 | 전기 사용량, 역률, 이산화탄소 배출량, 부하 수준 |
| 없는 정보 | 기계별 사용량, 생산량, 제품 종류, 날씨, 전기요금 |
| 공개 출처 | UCI 머신러닝 저장소 (출처 표기 필요) |

원본은 매일 마지막 15분(23:45~24:00)을 그날의 `00:00`으로 기록합니다. 밤 기록이 새벽으로 잘못 옮겨 가지 않도록, 파일의 줄 순서를 기준으로 시간을 다시 계산해서 사용합니다. 이 보정은 데이터를 데이터베이스에 넣는 단계에서 한 번 적용합니다.

### 데이터 보관 방식

- 원본 전력 데이터 35,040건을 데이터베이스에 한 번 넣어 두고, 앱은 읽기만 합니다.
- 사용자의 질문, 대화, 보고서, 접속 정보는 데이터베이스에 저장하지 않습니다. 이는 로그인과 대화 기록 저장을 제외한 PRD의 조건과 같습니다.
- 화면은 데이터베이스에 직접 접속하지 않습니다. 서버만 접속하므로 접속 정보가 화면에 노출되지 않습니다.
- 화면과 서버는 내 컴퓨터에서 실행하고, 데이터만 인터넷의 Supabase에 둡니다. 그래서 시연할 때 인터넷 연결이 필요합니다.
- 개발 중과 자동 테스트에서는 내 컴퓨터의 SQLite 파일을 데이터베이스로 씁니다. 시연할 때 Supabase로 바꿉니다.

## 4. 기능별로 할 수 있는 일

### 기능 1. 한눈에 보는 대시보드

사용자는 다음을 할 수 있습니다.

- 1년 치 전기 사용량을 숫자 카드로 확인합니다.
- 월별, 시간대별, 날짜별 그래프로 언제 전기를 많이 썼는지 확인합니다.

### 기능 2. 이상한 날 찾기

사용자는 다음을 할 수 있습니다.

- 유난히 많이 쓰거나 적게 쓴 날을 확인합니다.
- 추석처럼 공휴일이라 사용량이 적은 날은 공휴일 이름과 함께 확인합니다.
- 목록의 날짜를 눌러 그날의 일일 보고서를 엽니다.

비교 기준은 앞뒤 4주 동안의 비슷한 날입니다. 평일은 평일끼리, 주말은 주말끼리 비교합니다.

목록에는 탐지된 날 중 상위 8일을 평소와 다른 정도가 큰 순서로 보여 줍니다. 이 순서는 단순한 증가율이 아니라, 평소의 들쭉날쭉한 정도까지 고려한 이상 점수로 정합니다.

### 기능 3. 일일 보고서 자동 생성

사용자는 다음을 할 수 있습니다.

- 날짜를 고릅니다.
- 그날의 사용량, 평소 대비 차이, 최대 사용 시각 등을 표로 확인합니다.
- 화면의 버튼을 눌러 보고서를 `.md` 파일로 저장합니다.

### 기능 4. 말로 묻는 AI 에이전트

사용자는 다음을 할 수 있습니다.

- "1월과 9월을 비교해줘"처럼 평소 말투로 질문합니다.
- AI가 필요한 분석을 골라 실행한 결과를 그래프와 설명으로 확인합니다.

처음 쓰는 사람을 위해 추천 질문 4개를 제공합니다.

- 12월 16일 일요일에 왜 전력을 많이 썼을까?
- 역률이 낮은 시간대와 개선 방향을 알려줘
- 1월과 9월을 비교해줘
- 최대 수요전력을 10% 낮추면 어떻게 돼?

AI는 다음과 같은 순서로 답합니다.

1. 사용자의 질문을 읽고 필요한 분석을 판단합니다.
2. 분석 프로그램이 데이터로 숫자를 계산합니다.
3. 앱이 계산 결과로 그래프를 그립니다.
4. AI가 결과의 의미를 쉬운 말로 설명합니다.

### 기능 5. 한눈에 보기 (자동 요약)

생산직 작업자를 위한 기능입니다. 사용자는 다음을 할 수 있습니다.

- 날짜를 고르면 질문하지 않아도 그날의 요약이 자동으로 나옵니다. 일일 보고서와 같은 날짜를 씁니다.
- 상태를 신호등 색으로 봅니다. **좋음(초록), 주의(노랑), 이상(빨강)** 세 가지입니다.
- 쉬운 말로 쓴 세 줄 요약(얼마나 썼는지, 가장 많이 쓴 때, 전기 효율)과 **할 일** 한 가지를 봅니다.

상태와 숫자는 분석 프로그램이 정하고, AI는 그 숫자로 쉬운 문장만 씁니다. AI 문장에 계산 결과에 없는 숫자가 들어 있으면 그 문장을 버리고 프로그램이 만든 문장을 보여 줍니다. API 키가 없거나 AI가 실패해도 프로그램이 만든 요약은 나옵니다.

### 기능 6. 경보 예측 (조기 대응)

생산직 작업자와 에너지 담당자를 위한 기능입니다. 실시간 데이터가 없으므로 2018년 데이터의 한 시각을 "지금"으로 정해서 시험합니다. 사용자는 다음을 할 수 있습니다.

- 시각을 고르면 앞으로 1시간 안에 두 가지 기준을 넘을 가능성을 봅니다.
  - **사용량:** 15분 수요전력이 기준을 넘는지 봅니다. 기준은 1~8월 15분 수요전력의 상위 5%입니다.
  - **역률:** 85% 아래로 떨어지는지 봅니다. 09~22시만 봅니다.
- 위험 정도를 **좋음, 주의, 위험** 세 가지로 보고, 미리 할 일을 봅니다.
- 이 예측이 과거에 얼마나 맞았는지(채점 결과)를 봅니다.
- 고른 날짜 하루의 경보와 실제로 기준을 넘은 때를 한 줄씩 겹쳐 보고(**하루 경보 타임라인**), 그날 경보가 몇 분 먼저 울렸는지 확인합니다.

예측은 분석 프로그램의 머신러닝 모델이 계산합니다. AI(OpenAI)는 예측하지 않습니다. AI 에이전트에게 "10월 10일 오후 1시에 위험해?", "12월에 경보가 가장 많은 시간대는?"처럼 물으면 AI가 예측 도구를 불러 그 결과로 답합니다. 예측은 확률이라 틀릴 수 있으므로, 화면에 채점 결과와 함께 보여 줍니다. 경보는 알리기만 하고 기계를 제어하지 않습니다.

### 기능 7. 역률 개선 계산기

에너지 담당자와 설비 담당자를 위한 기능입니다. 사용자는 다음을 할 수 있습니다.

- 기간과 목표 역률(85%, 90%, 95%)을 고르면, 09~22시 역률을 목표까지 올리는 데 필요한 콘덴서 용량(kVar)을 봅니다.
- 필요한 만큼만 단계적으로 켜지는 **자동 역률 조정기**의 추천 용량과, 같은 용량을 늘 켜 두는 **고정 콘덴서**를 달았을 때를 비교합니다. 고정 콘덴서는 부하가 가벼울 때 과보상(진상)되어 오히려 나빠질 수 있습니다.
- 어느 시간대에 보상이 가장 부족한지 그래프로 봅니다.
- AI 에이전트에게 "역률을 90%로 맞추려면 콘덴서를 얼마나 달아야 해?"처럼 물어도 같은 계산으로 답합니다.

15분 평균 데이터로 한 산술 계산이므로 실제 용량은 현장 측정과 전문가 검토로 정합니다. 금액은 계산하지 않습니다.

### 기능 8. 감시 재생 (경보 자동 감시 시연)

실시간 데이터가 없으므로, 2018년의 하루를 15분씩 흘려보내며 "그때 이 시스템이 있었다면 어떻게 알렸을지"를 보여 주는 시연 기능입니다. 사용자는 다음을 할 수 있습니다.

- 날짜를 고르고 재생하면 시계가 00:00부터 15분씩 흘러갑니다(느리게·보통·빠르게). 멈추거나 막대로 원하는 시각으로 옮길 수 있습니다.
- 지금 시각의 사용량·역률 경보(좋음·주의·위험)와 할 일, 지금까지의 15분 사용량 그래프를 봅니다.
- 경보가 켜질 때, 실제로 기준을 넘을 때(경보가 몇 분 먼저 알렸는지), 헛경보로 끝났을 때 **알림**이 한 줄씩 쌓입니다.
- 하루가 끝나면 그날의 채점 문장을 봅니다.

경보 계산은 기능 6과 같은 모델입니다. 재생일 뿐 실제 감시가 아니며, 화면에도 그렇게 밝힙니다. 경보는 알리기만 하고 기계를 제어하지 않습니다.

### 기능 9. 경보 이유와 대응 기록

경보를 믿고 쓸 수 있게 "왜 울렸는지"를 보여 주고, 작업자의 판단을 모아 경보를 개선하는 근거로 씁니다. 사용자는 다음을 할 수 있습니다.

- 주의·위험 경보에서 **왜 그렇게 봤는지** 이유(최대 3개)를 봅니다. 각 이유는 그 정보를 평소 같은 값으로 바꾸면 확률이 몇 %p 내려가는지로 잽니다.
- 켜진 경보에 **조치함 / 무시함 / 오경보였음**을 눌러 기록합니다. 경보 예측 탭과 감시 재생 탭의 알림에서 누를 수 있습니다.
- 쌓인 기록의 통계(응답 수, 시간대별 오경보)와 "주의 문턱을 올리면 오경보가 몇 번 사라지고 필요했던 경보를 몇 번 놓치는지"를 봅니다.

경보 기준은 자동으로 바뀌지 않습니다. 기준을 바꿀지는 사람이 정합니다. 기록은 이 컴퓨터의 파일에만 저장하고 데이터베이스에는 쓰지 않습니다.

### 기능 10. 교대 인수인계서 자동 작성

생산직 작업자와 반장을 위한 기능입니다. 교대는 A조 06~14시, B조 14~22시, C조 22시~다음 날 06시입니다. 사용자는 다음을 할 수 있습니다.

- 날짜와 조를 고르면 그 조의 인수인계서를 봅니다. 요약 세 줄, 인계 사항, 다음 조가 먼저 확인할 것, 근거 숫자, 참고 매뉴얼이 들어 있습니다.
- 인계 사항에는 응답하지 않은 경보, 실제로 기준을 넘은 때와 경보가 몇 분 먼저 알렸는지, 평소보다 30% 넘게 다른 사용량, 낮은 역률이 들어갑니다.
- 다음 조 시작 1시간의 경보 예측(기능 6)과 할 일이 들어갑니다.
- `.md` 파일로 저장합니다.

숫자와 상태(좋음·주의·확인 필요)는 코드가 정하고 AI는 문장만 다듬습니다. AI 문장에 사실에 없는 숫자가 있거나 매뉴얼 출처 표기가 빠지면 버리고 코드 문장을 씁니다.

### 기능 11. 자동 실행

- 교대가 끝나면 사람이 화면을 열지 않아도 인수인계서와 일일 보고서가 파일로 만들어지고, 원하면 메신저(Incoming Webhook)로 보내집니다(`python -m app.autorun`).
- 감시 재생(기능 8)에서 교대 시각(06:00·14:00·22:00)이 지나면 "인수인계서를 자동으로 작성했어요" 알림과 문서가 뜹니다.

### 기능 12. 현장 매뉴얼 검색 (RAG)

- 매뉴얼 탭에서 질문으로 매뉴얼 절을 찾고, 문서를 읽습니다. 관련 문서가 없으면 없다고 보여 줍니다.
- AI 에이전트는 절차를 물으면 매뉴얼을 찾아 그 내용으로만 답하고 출처를 붙입니다. 출처를 누르면 매뉴얼 탭으로 옮깁니다.
- 경보 카드의 "조치 매뉴얼 보기"는 그 경보의 대응 절을 늘 같게 보여 줍니다(AI 없이 검색만).
- 첫 버전의 매뉴얼은 시연용 예시 문서이며, 화면과 문서에 그렇게 밝힙니다.

### 기능 13. AI 답변 숫자 검증과 자동 평가

- 대화 답변 아래에 숫자 검증 결과(모두 일치 / 찾지 못한 숫자 목록)를 보여 줍니다.
- 개발자는 질문 세트로 에이전트를 자동 채점(도구 선택, 숫자 근거, 금지 규칙)해 프롬프트나 모델을 바꾼 뒤 나빠졌는지 확인합니다.

### 기능 14. 조치 에이전트

에너지 담당자와 현장 반장을 위한 기능입니다. 경보를 보고 "무엇을 하세요"라고 말하는 데서 그치지 않고, 에이전트가 조치까지 합니다. 사용자는 다음을 할 수 있습니다.

- 경보 시각을 고르거나 경보 예측 카드에서 "조치 에이전트에게 맡기기"를 누르면, 에이전트가 경보를 조사하고 조치를 시뮬레이션한 뒤 제안합니다.
- 위험도 낮은 조치(담당자 알림, 작업지시서 발행)는 바로 실행됩니다. 설비에 닿는 조치(큰 설비 기동 연기, 보조 설비 잠시 정지, 콘덴서 단계 투입)는 작업자가 **승인**해야 가상 공장에 실행되고, **되돌릴** 수 있습니다.
- 실행 뒤에는 실제 2018년 기록으로 조치 전후를 비교한 채점 결과(그래프)를 봅니다. 해결되지 않으면 에이전트가 다시 계획하거나 사람에게 넘깁니다.
- 에이전트가 무엇을 보고 무엇을 했는지, 누가 승인했는지 모든 단계를 기록으로 봅니다.

허용된 조치, 입력 한도, 승인 규칙은 코드가 강제합니다. 설비 조치는 실제 설비가 아니라 가상 공장에만 적용합니다. API 키가 없으면 같은 안전장치를 쓰는 규칙 계획자가 계획합니다.

### 모든 기능에 적용하는 약속

| 약속 | 내용 |
|---|---|
| 숫자는 프로그램이 계산합니다. | AI가 숫자를 지어내지 않도록 계산은 분석 프로그램이 맡고, 그래프도 계산 결과로만 그립니다. |
| 사실과 추측을 나눕니다. | 기계별 데이터가 없어 정확한 원인은 단정하지 않습니다. 추측은 "가능성"으로 표시하고 확인 방법을 제안합니다. |
| 모르는 금액은 말하지 않습니다. | 전기요금 정보가 없으므로 원화 금액을 제시하지 않습니다. |
| 설비는 사람이 승인합니다. | AI는 실제 공장 기계를 제어하지 않습니다. 조치 에이전트의 설비 조치는 작업자 승인 뒤 가상 공장에만 실행됩니다. |

## 6. 첫 버전 완성 기준

아래를 모두 만족하면 첫 버전이 완성된 것입니다.

### 기능 완성

- [ ] 대시보드에서 1년 치 사용량과 월별, 시간대별, 날짜별 그래프를 볼 수 있다.
- [ ] 평소와 다른 날을 확인할 수 있고, 공휴일 이름이 함께 표시된다.
- [ ] 날짜를 고르면 일일 보고서가 표로 나오고, 화면의 버튼으로 `.md` 파일을 저장할 수 있다.
- [ ] 실제 AI에게 평소 말투로 질문하고 그래프와 함께 답을 받을 수 있다.
- [ ] 날짜를 고르면 질문하지 않아도 상태 신호등과 쉬운 세 줄 요약, 할 일이 나온다.
- [ ] 시각을 고르면 앞으로 1시간의 사용량·역률 경보와 할 일이 나오고, 채점 결과를 함께 볼 수 있다.
- [ ] 하루 경보 타임라인에서 경보가 실제 초과보다 먼저 켜졌는지 볼 수 있다.
- [ ] 목표 역률을 고르면 추천 콘덴서 용량과 고정 콘덴서 비교가 나온다.
- [ ] 날짜와 조를 고르면 인수인계서가 나오고, 응답하지 않은 경보가 인계 사항에 들어간다.
- [ ] `app.autorun`이 인수인계서 파일을 만들고 웹훅으로 보낸다.
- [ ] 절차 질문에 AI가 매뉴얼 출처를 붙여 답하고, 매뉴얼에 없는 절차는 지어내지 않는다.
- [ ] AI 답변 아래에 숫자 검증 결과가 보인다.
- [ ] 조치 에이전트가 낮은 위험 조치는 바로 실행하고, 설비 조치는 승인 뒤에만 실행하며, 결과를 실제 기록으로 채점한다.

### 품질 확인

- [ ] 추천 질문 4개에 AI가 실제 데이터를 기반으로 답한다.
- [ ] AI가 말한 숫자가 분석 프로그램의 계산 결과와 일치한다.
- [ ] AI가 원인을 단정하지 않고 사실과 가능성을 구분한다.
- [ ] 처음 보는 사람이 설명 없이 3분 안에 질문하고 결과를 이해한다.
- [ ] 공모전 발표에서 3분 안에 문제, 해결 방법, 발견한 내용을 시연할 수 있다.

## 7. 이번에 만들지 않는 기능

| 만들지 않는 기능 | 이유 |

| 공장 설비와 실시간 연결 | 실제 공장이 없고, 공개된 과거 데이터로 먼저 검증합니다. |
| AI가 실제 기계를 직접 제어 | 잘못되면 위험하므로 설비 조치는 승인을 받아 가상 공장에만 합니다. 실제 설비 연동(PLC·SCADA)은 하지 않습니다. |

| 다른 공장 데이터 업로드 | 한 공장의 데이터로 핵심 기능부터 검증합니다. |
