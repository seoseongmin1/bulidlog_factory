# 공장 에너지 에이전트

철강 공장의 전력 데이터를 자연어로 분석하고, 교대 인수인계처럼 반복되는 현장 문서 작업을 자동으로 처리하는 AI 에이전트입니다. "12월 16일 일요일에 왜 전력을 많이 썼을까?"라고 물으면 에이전트가 필요한 분석 도구를 골라 실행하고, 그래프와 함께 사실과 가설을 구분해 답합니다. 기획 문서는 [docs](docs)에 있습니다.

| 기능 | 내용 |
|---|---|
| 대시보드·이상한 날 | 연간 사용량, 최대 수요전력, 역률, CO2와 월별·시간대별·날짜별 그래프. 아래에 주변 같은 요일 유형과 비교해 평소와 가장 다른 8일을 보여 주고, 날짜를 누르면 "하루 보기"로 옮겨 그날의 보고서가 열립니다. |
| 하루 보기 | 생산직용 한눈에 보기(상태 신호등·쉬운 세 줄 요약·할 일)와 일일 보고서(`.md` 저장). 숫자와 상태는 계산으로 정하고 AI는 문장만 다듬습니다. |
| **교대 인수인계 (새 기능)** | A조(06~14시)·B조(14~22시)·C조(22~06시)가 끝나면 그 조의 사용량과 평소 대비, 켜진 경보와 실제 초과, 작업자 응답, **응답하지 않은 경보**, 다음 조 시작 1시간 경보, 참고 매뉴얼을 모아 인수인계서를 자동으로 씁니다. AI 문장에 사실에 없는 숫자가 있거나 매뉴얼 출처가 빠지면 버리고 코드가 쓴 문장을 씁니다. |
| **자동 실행 (새 기능)** | `python -m app.autorun --now --send`를 작업 스케줄러에 걸면 교대가 끝날 때마다 인수인계서를 파일로 남기고 메신저(웹훅)로 보냅니다. 감시 재생에서도 교대 시각이 지나면 "인수인계서를 자동으로 작성했어요" 알림과 문서가 뜹니다. |
| **현장 매뉴얼 검색·RAG (새 기능)** | 예시 매뉴얼 8개를 절 단위로 색인해 질문과 가까운 절을 찾습니다. AI 에이전트는 `search_manual` 도구로 찾은 절만 근거로 절차를 답하고 `[SOP-EN-02 2. 경보가 켜지면]`처럼 출처를 붙입니다. 경보 카드의 "조치 매뉴얼 보기"와 인수인계서의 참고 매뉴얼도 같은 검색을 씁니다. |
| AI 에이전트 | 평소 말투로 질문하면 분석 도구 15개(매뉴얼 검색·교대 인수인계 포함) 중 필요한 것을 골라 답합니다. |
| **답변 숫자 검증 (새 기능)** | 답변의 숫자를 이번 대화의 도구 결과와 하나씩 대조해, 답변 아래에 "✓ 숫자 12개 모두 계산 결과와 일치" 또는 "⚠ 1개는 찾지 못했어요: 194"를 붙입니다. |
| **에이전트 자동 평가 (새 기능)** | `python -m app.evals`가 질문 14개를 실제 모델에 보내 도구 선택, 숫자 근거, 금지 규칙(금액·설비 제어·범위 밖)을 코드로 채점하고 표를 남깁니다. 프롬프트나 모델을 바꿨을 때 나빠졌는지 확인하는 용도입니다. |
| **조치 에이전트 (새 기능)** | 경보 하나를 맡아 **조사 → 시뮬레이션 → 조치 → 실제 기록으로 검증 → 안 되면 재계획**까지 합니다. 알림·작업지시서는 바로 실행하고, 설비에 닿는 조치(기동 연기, 보조 설비 정지, 콘덴서 투입)는 작업자가 승인해야 **가상 공장**(2018년 기록 위의 시뮬레이터)에 실행합니다. 허용 조치·한도·승인 규칙은 프롬프트가 아니라 코드가 강제하고, 모든 단계를 누가 했는지와 함께 기록합니다. 경보 예측 카드의 "조치 에이전트에게 맡기기"로 바로 넘어갑니다. |
| 경보 예측 | 2018년의 한 시각을 "지금"으로 보고, 1시간 안에 사용량(408.1kW 초과)이나 역률(85% 미만, 09~22시)이 기준을 넘을 확률과 위험 정도를 머신러닝으로 계산합니다. 경보 이유, 할 일, 조치 매뉴얼, 지난 채점 결과, 하루 경보 타임라인을 함께 보여 줍니다. |
| 감시 재생 | 2018년의 하루를 15분씩 흘려보내며 경보가 언제 켜지고 몇 분 먼저 알렸는지, 헛경보는 언제였는지, 교대 인수인계서가 언제 만들어지는지를 알림으로 보여 줍니다. 실시간 데이터가 아니라 기록 재생입니다. |
| 경보 대응 기록 | 작업자가 조치함·무시함·오경보를 누르면 이 컴퓨터의 파일(`backend/local/`)에 기록해 통계와 "문턱을 올리면 어떻게 되는지"를 보여 줍니다. 응답하지 않은 경보는 인수인계서로 넘어갑니다. |
| 역률 개선 계산기 | 기간과 목표 역률을 고르면 자동 역률 조정기 용량(kVar)을 추천하고 고정 콘덴서와 비교합니다. 금액은 계산하지 않습니다. |

화면 왼쪽은 위쪽 탭(개요, 하루 보기, 교대 인수인계, 경보 예측, 조치 에이전트, 감시 재생, 역률 개선, 매뉴얼)으로 나눠 하나씩 보여 주고, 오른쪽 AI 대화는 늘 보입니다.

### AI가 믿을 만하게 일하도록 만든 장치

| 장치 | 어디에 | 방식 |
|---|---|---|
| 숫자는 코드가 계산 | 모든 기능 | AI는 도구 결과를 설명만 합니다. 그래프도 도구 결과로만 그립니다. |
| 숫자 검증(grounding) | 대화, 한눈에 보기, 인수인계서 | `app/grounding.py`가 문장의 숫자를 계산 결과에서 찾습니다. 한눈에 보기·인수인계서는 하나라도 없으면 AI 문장을 버리고, 대화는 화면에 표시합니다. |
| 근거 문서 검색(RAG) | 대화, 경보 카드, 인수인계서 | `app/knowledge.py`. 절차는 매뉴얼에서 찾은 절만 쓰고 출처를 붙입니다. 관련 문서가 없으면 빈 결과를 돌려줘 AI가 지어내지 않게 합니다. |
| 자동 평가(evals) | 에이전트 전체 | `app/evals.py`와 `evals/cases.json`. 바꾼 뒤 점수를 비교합니다. |
| 사람이 결정 | 경보 기준, 설비 조치 | 경보 기준은 대응 기록을 보고 사람이 바꿉니다. 조치 에이전트의 설비 조치는 작업자 승인 뒤에만, 가상 공장에만 실행되고 되돌릴 수 있습니다. |
| 행동 안전장치 | 조치 에이전트 | `app/actions.py`. 허용된 조치 5가지, 입력 한도(최대 kW·단수·시간 범위·지난 시각 금지), 위험도별 승인, 사건당 조치 6개, 감사 기록(`backend/local/action_log.jsonl`). 한도를 넘는 제안은 거부되어 에이전트에게 오류로 돌아갑니다. |
| 결과로 채점 | 조치 에이전트 | 에이전트는 예상값(평소 + 지금의 차이)과 불확실성(8월 기준 80% 분위 약 140kW)만 보고 계획하고, 실행 결과는 실제 2018년 기록으로 채점합니다. |

### 이번에 정리한 것

- **내일 예측 탭을 없앴습니다.** 지난 4주 비율로 정한 규칙이라 헛경보가 많았고, 1시간 경보 예측(머신러닝)과 겹쳤습니다.
- **이상한 날 탭을 개요 탭 아래로 합쳤습니다.**
- 더 쓰지 않는 `database/energy.db`, 옛 시제품 기준의 `docs/mvp.md`, 다른 프로젝트 설명이 남아 있던 `docs/README.md`, 화면 저장 버튼과 겹치던 `app/report.py`를 지웠습니다. 일일 보고서 파일 만들기는 `app.autorun`이 합니다.

## 구성

```
화면 (React, frontend/)  ──/api──▶  서버 (FastAPI, backend/)  ──▶  데이터베이스 (database/)
                                       └──▶ OpenAI API
```

- **화면:** 데이터베이스에 직접 접속하지 않습니다. 서버만 접속하므로 접속 정보가 화면에 노출되지 않습니다.
- **데이터베이스:** 원본 전력 데이터 35,040건만 넣습니다. 질문, 대화, 보고서는 저장하지 않습니다.
  - `backend/.env`의 `DATABASE_URL`(Supabase Session pooler 주소)로 접속합니다. 없으면 SQLite로 넘어가지 않고 오류와 확인할 항목을 알려 줍니다.
  - 자동 테스트만 임시 SQLite를 씁니다.
- **계산:** 모든 수치는 서버의 분석 코드가 계산하고, AI 모델(OpenAI)은 결과를 해석합니다. 그래프도 계산 결과로만 그립니다.

## 처음 한 번 (Windows PowerShell)

Python 3.15와 Node.js 26에서 확인했습니다.

```powershell
cd backend
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-dev.txt
copy .env.example .env
cd ..\frontend
npm install
```

`backend/.env`에 [OpenAI API 키](https://platform.openai.com/api-keys)를 넣으세요. 모델은 기본 `gpt-5`이고, `OPENAI_MODEL`로 바꿀 수 있습니다. 키는 사용한 만큼 요금이 나오며 다른 사람에게 보여 주면 안 됩니다. 키가 없어도 대시보드, 이상한 날, 보고서는 작동합니다.

```
OPENAI_API_KEY=발급받은_키
```

## 실행

```powershell
.\start.cmd
```

브라우저에서 http://localhost:8000 을 엽니다. 이 명령은 다음을 알아서 합니다.

1. 화면이 아직 빌드되지 않았으면 빌드합니다.
2. 데이터베이스에 전력 데이터가 없으면 `database/steel_industry_data.csv`에서 넣습니다.
3. 서버를 켭니다. 서버가 빌드된 화면도 함께 제공합니다.

포트를 바꾸려면 `.\start.cmd -Port 8001`을 씁니다.

## 자동 실행 (교대 인수인계서·일일 보고서)

```powershell
cd backend
.venv\Scripts\python -m app.autorun --date 2018-10-10              # A·B·C조 인수인계서 + 일일 보고서를 backend/local/outbox/2018-10-10/에 저장
.venv\Scripts\python -m app.autorun --date 2018-10-10 --shift B --send   # B조만 만들어 메신저로 보냄
.venv\Scripts\python -m app.autorun --now --send                  # 지금 시각을 2018년 같은 날·시각으로 보고 방금 끝난 교대를 보냄
```

메신저로 보내려면 `backend/.env`에 `HANDOVER_WEBHOOK_URL`(Slack·Teams·Mattermost의 Incoming Webhook 주소)을 넣습니다. 교대가 끝날 때마다 자동으로 받으려면 Windows 작업 스케줄러에 06:05, 14:05, 22:05로 등록합니다.

```powershell
schtasks /Create /TN "인수인계-A조" /SC DAILY /ST 14:05 /TR "cmd /c cd /d C:\경로\backend && .venv\Scripts\python -m app.autorun --now --send"
```

데이터가 2018년 기록이라 `--now`는 오늘을 2018년의 같은 날로 바꿔 씁니다. 실제 공장 데이터에 붙이면 이 바꾸기만 빼면 됩니다.

## 조치 정책 채점

```powershell
cd backend; .venv\Scripts\python -m app.actions      # 9~12월 사용량 경보 사건에 정책별로 조치해 보고 실제 기록으로 채점 (약 15초)
```

| 정책 | 사건 | 실제로 넘은 사건 | 완전 해결 | 오히려 악화 | 넘은 15분 칸 | 기준 초과 에너지 |
|---|---|---|---|---|---|---|
| 조치 안 함 | 363 | 196 | 0 | 0 | 542 | 6,970kWh |
| 무조건 미루기 | 363 | 196 | 40 | 43 | 461 | 10,804kWh (+55%) |
| 규칙 계획자 | 363 | 196 | 29 | 3 | 398 | 4,768kWh (−32%) |

사람이 흔히 떠올리는 "큰 설비 기동 미루기"는 다음 시간에도 부하가 높으면 미룬 부하가 다시 기준을 넘겨 초과 에너지를 오히려 55% 늘렸습니다. 그래서 규칙 계획자와 AI 에이전트의 지시문 모두 "다음 1시간에 여유가 있을 때만 미루고, 아니면 보조 설비 정지 + 사람에게 넘기기"를 따릅니다. 완전 해결이 15%에 그치는 것은 허용된 조치의 한도(보조 설비 최대 40kW) 때문이며, 나머지는 에이전트가 에너지 담당에게 넘깁니다.

## Supabase로 바꾸기

1. [Supabase](https://supabase.com/)에서 프로젝트를 만들고 데이터베이스 비밀번호를 정합니다.
2. 프로젝트 상단 **Connect > Session pooler**의 연결 문자열을 `backend/.env`에 `DATABASE_URL=...`로 넣습니다. 자세한 형식은 `backend/.env.example`에 있습니다.
3. 데이터를 넣습니다. 표를 만들고, 외부에서 이 표를 읽거나 바꾸지 못하도록 행 수준 보안(RLS)도 자동으로 켭니다.
   ```powershell
   cd backend
   .venv\Scripts\python -m app.loader
   ```
4. 서버를 다시 켜면 Supabase를 씁니다. 무료 플랜은 오래 쓰지 않으면 프로젝트가 일시 중지될 수 있으니, 시연 전에 확인하세요.

인터넷 없이 시연하려면 `DATABASE_URL=sqlite:///../database/energy.db`로 두고 `python -m app.loader`를 한 번 실행하면 됩니다.

- 공장 전체 전력만 있어 설비별 원인을 특정할 수 없습니다. 에이전트는 원인을 단정하지 않고 가능성으로 말합니다.
- 전기요금 데이터가 없어 금액을 계산하지 않습니다.
- 조치 에이전트의 설비 조치는 가상 공장에만 적용됩니다. 조치 효과는 단순한 모델(미루기는 에너지를 뒤로 옮김, 보조 설비 정지는 칸 사용량의 30%까지, 콘덴서는 1단 10kVar)이라 실제 설비 특성과 다를 수 있습니다.
- 현장 매뉴얼(`backend/knowledge/`)은 시연용 예시 문서입니다. 실제 공장 문서로 바꾸면 그대로 검색됩니다.
- 매뉴얼 검색은 인터넷과 키 없이 도는 TF-IDF(낱말 + 글자 묶음)입니다. 문서가 수백 개로 늘면 임베딩 검색으로 바꾸는 것이 좋습니다.
- 로그인과 사용량 제한이 없는 로컬 시연용입니다. 인터넷에 공개하면 다른 사람이 내 API 키로 요금을 쓸 수 있습니다.
